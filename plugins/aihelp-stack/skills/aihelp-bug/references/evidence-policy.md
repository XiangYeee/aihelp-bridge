# AIHelp 排查问题规则

## 基本原则

- 先根据问题确定所在的AIHlep项目。
- 定位相关代码，结合问题提供的线索和实际数据来定位代码链路，根据代码链路来查日志。
- 不要停在第一个可疑点，要沿上下游链路确认真正的问题点。
- 结论必须建立在可验证证据上
  - 证据至少包含一项事实验证，不限于数据库、日志、配置、缓存、客诉（Ticket）操作记录。
  - 应优先补充当前场景下最强、最直接、最接近事实源头的证据。

## 链路排查

- 如果问题可能由上游输入、MQ 投递、下游消费、延迟任务执行、缓存状态或持久化快照漂移引起，在结束结论前必须检查这些链路。
- 如果问题跨服务边界，先识别边界，再检查边界两侧。
- 可以在`aihelp-elk` MCP中定位关键日志，使用`traceId`连接上下文进行排查。

## 按场景补证据

- 运行时行为、请求失败、线上异常、环境差异或 trace 执行链路问题，使用 `aihelp-elk` MCP。
- 值、数量、状态、记录、计费结果、快照、持久化结果或分页结果差异问题，使用 `aihelp-db` MCP。
- 当可见结果不一定直接来自当前请求链路时，要把缓存、快照、聚合表和持久化结果视为一等证据来源。
- 配置值或数据库连接信息相关问题，使用 `aihelp-apollo` MCP。
- `test` 或 localhost 启动场景，优先使用项目本地 `test` 配置作为数据库连通来源。
- 非 `test` 环境中的数据库 Apollo 值通常是环境内 DNS 或内网地址，默认当前机器不可访问，需要使用`aihelp-account` MCP 来查询对应环境数据库地址。
